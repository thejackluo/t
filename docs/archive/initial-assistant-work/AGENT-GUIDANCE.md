# T Run project guidance

> Archived assistant guidance. Paths and workflow assumptions below describe the former active layout.

- Read `docs/planning/STATE.md`, `docs/planning/PROJECT.md`, and the relevant roadmap phase before implementing. `.planning` is a compatibility symlink to `docs/planning/`; keep one canonical copy of these files.
- Give concise status updates listing the work in progress.
- Treat the current station scope and record rules as provisional until the team confirms them.
- Preserve MBTA identifiers, platform distinctions, directed transfers, and source timestamps.
- Keep schematic display coordinates separate from geographic coordinates and routing costs.
- Label scheduled, predicted, and observed times distinctly. Never present a heuristic route as a proven optimum.
- Require explicit user instructions before committing, pushing, creating a remote repository, or submitting external applications.
- Store credentials locally and keep raw attempt evidence out of Git.
- The first deliverable is a useful manual map-and-itinerary editor; optimization builds on validated timetable routing.
- Silver Line support is requested for later delivery (Phase 7); keep route modes and required-stop inventories configurable.
